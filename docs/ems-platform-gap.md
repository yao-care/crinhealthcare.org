# 油水電氣資料治理平台｜現況差距分析

> 2026-11-15。對照對象：`docs/ems-platform-prd.md`（PRD V1.0，2026-11-15）與 `services/ems-admin` 現況。
> 參考資料：業主提供的《碳盤查資料收集表單.xlsx》（工作表「碳排放活動數據」A1:F36，32 項活動來源）。

## 業主決定（2026-11-15）

- **在現有 ems-admin 上擴充**，不另起新系統。
- **一人一帳號、分角色**（PRD §3 九種角色；權限＝組織範圍＋標的範圍＋操作動作）。
- **一次全部做完**（PRD §23 WP1–WP6 全部納入，不留「未來擴充」）。

## 結論

現有系統約涵蓋 PRD 的三分之一。缺的主要是**資料骨架**：PRD §5 的「標的／來源／原始觀測／採用值／成果引用」五層，現況一層都沒有分開（每期只存一筆值，沒有審核、定版與引用鏈）。

## 實作前提

- production 的 pm2 `ems-admin` 工作目錄就是本 repo 的 `services/ems-admin`，`public/` 存檔即上線。改版在獨立 git worktree 開發、隔離實例測試，完成後再合回 main 並重啟。
- 新資料骨架改用主機本地 SQLite（Node 22 內建 `node:sqlite`），放在 `AUDIT_DATA_DIR` 底下、不進 public repo。
- 一人一帳號需要院方提供各院承辦、審核、核准人員名單；在拿到之前，現有 16 組院所帳號沿用為各院的院所管理者。

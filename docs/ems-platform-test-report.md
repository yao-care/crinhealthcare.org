# 油水電氣資料治理平台｜測試報告

> 測試日期：2026-11-15。對應 PRD §21 非功能需求、§22 驗收項目、§23.2 第 7 項交付物。
> 環境：主機 4 核心、7 GB 記憶體，Node.js 22.23.4，SQLite（WAL），單一 pm2 程序。負載測試的用戶端與伺服器在同一台主機，數字偏保守。
> 測試資料：隔離實例上的示範資料（一家院所一整年、11 個標的、約 100 筆採用值），另加 5,000 筆大量匯入；**不含正式院所資料**。

## 1. 總結

| 類別 | 結果 |
|---|---|
| 自動化測試（服務全部） | 202 項全過 |
| 平台驗收測試（PRD §22 逐條＋ISO 14064-1＋HTTP 層） | 41 項全過 |

| 大量匯入 5,000 列 | 預檢 0.4 秒、提交 2.6 秒，零錯誤；同檔重送不重複寫入 |

## 2. 功能與驗收測試（`test/platform.test.js`、`test/platform-http.test.js`）

測試名稱前的編號是 PRD §22 驗收清單的節次。

- ✅ 舊院所帳號登入 → 平台可用、舊入口有院所範圍
- ✅ 院所管理者建立個人帳號 → 首次登入只能改密碼
- ✅ 未登入 401、沒權限 403（中文訊息）、跨來源 POST 403
- ✅ 上傳佐證（multipart）＋下載留稽核＋檔案型態檢查
- ✅ OpenAPI 文件可取得
- ✅ 推送介接：權杖錯誤 401、正確才寫入、重送冪等
- ✅ 平台前端頁面可載入
- ✅ [seed] 院所階層：分院掛在總院下，群組節點存在
- ✅ [22.1] 未指定部門、未知保管者仍可新增四類標的
- ✅ [22.1] 一物一碼：同院區同類型同識別碼不可重複建檔
- ✅ [22.1] 標的修改要原因、停用保留歷史
- ✅ [22.1] 不適用判定須填原因並由另一人核准
- ✅ [22.1] 從候選線索建立追查、詢問、轉介、找到後寫入知識庫
- ✅ [22.1] 同一指標保存多來源、不同期間觀測；計費期間依日數分攤
- ✅ [22.1] 原始觀測不可覆寫：修正產生新版本，舊版保留
- ✅ [22.1] 缺漏、不適用、實際零值、未知可區分；缺漏不可填 0
- ✅ [22.1] OCR 結果須人工確認才能成為觀測值
- ✅ [22.1] 累積讀值：差分、換表、回零、倍率
- ✅ [22.1] 檢核：同邊界同期間跨來源差異開案；分攤值只提示；歷史規則；油槽平衡
- ✅ [22.1] 共用油槽平衡：多台共用不重複計數
- ✅ [22.1] 差異案件生命週期：指派→補件→提出方案→核准結案
- ✅ [22.1] 裁決：理由必填、提出者不可自審、高影響需兩位、未檢核不得採用
- ✅ [22.1] 已定版資料不可改；新版本不影響原版
- ✅ [22.2] 計算：版本化係數、展開計算、缺漏不當 0
- ✅ [22.2] 報告：就緒度、送審條件、三人分權、封存、重現、匯出四種格式
- ✅ [22.2] 已定版資料修改建立新版本，原報告仍可重現
- ✅ [22.2] 成果回饋：第一線看得到被哪些報告引用
- ✅ [22.2] 看板分級：公開層不含費用、識別碼；KPI 分開算

- ✅ [22.3] 權限：跨院查詢被擋；稽核唯讀；系統管理員不能代替業務裁決
- ✅ [22.3] 稽核雜湊鏈完整、不可修改刪除
- ✅ [22.1][22.3] 匯入：預覽、錯誤清單、提交、同檔重送不重複、整批撤銷
- ✅ [22.3] 歷史碳盤查工作簿 32 項：保留座標、非油水電氣保留為參照

## 3. 瀏覽器實測

- 工具：Playwright（Chromium headless），桌機 1440×900、手機 390×844。
- 角色：盤點承辦、報告承辦、資料審核者、報告核准者、管理者、一般同仁、稽核、系統管理員。
- 每個角色逐頁開啟 29 個路由：沒有權限的頁面顯示中文「你沒有…權限」，選單也不出現；有權限的頁面全部載入，零 pageerror。
- 一般同仁登入後首頁導向「全院公開進度」，不會看到盤點明細。

**大量匯入**
```
上傳＋預檢 5,000 列：0.4 秒（可匯入 5000，錯誤 0）
提交 5,000 列：2.6 秒（{"created":5000,"duplicate":0,"new_version":0,"failed":0}）
檢核 2024 年 5,000 筆累積讀值：0.2 秒（{"observations":1464,"results":1098,"bySeverity":{"warning":1098}}）
```

判讀：
- 平台是單一 Node 程序，SQLite 查詢在主執行緒同步執行；50 人並行時延遲主要來自排隊，吞吐量約每秒 180 次請求，沒有錯誤。
- 以 16 家院所、每院同時上線數人估算，負載遠低於 20 人並行的測試情境。
- 若日後同時上線人數大幅增加，可改為多程序（pm2 cluster）加唯讀副本，或將長時間計算移到背景工作。

測試中發現並已修正：靜態檔原本每次請求都讀磁碟，50 人並行時前端程式檔中位數 0.9 秒；改為記憶體快取（檔案異動即重讀）後與 API 同級。

## 5. 安全與資料完整性

| 項目 | 驗證方式 | 結果 |
|---|---|---|
| 未登入、無權限、跨院查詢 | HTTP 測試＋單元測試 | 401／403，跨院資料不可見 |
| CSRF（跨來源 POST） | HTTP 測試 | 403 |
| 首次登入強制改密碼、登入鎖定、兩步驟驗證 | 單元測試 | 通過 |
| 原始觀測不可覆寫、定版資料集與封存報告不可修改、稽核事件不可改刪 | 直接對資料庫下 UPDATE／DELETE | 被資料庫 trigger 擋下 |
| 稽核雜湊鏈 | 驗證程式 | 完整 |
| 佐證檔雜湊、機敏分級、下載稽核 | 單元測試 | 通過 |
| 上傳檔：副檔名＋檔頭檢查、擋可執行檔 | 單元測試 | 不符格式與可執行檔拒絕 |
| 推送介接權杖 | HTTP 測試 | 錯誤權杖 401；重送冪等 |
| 備份與還原演練 | 單元測試 | integrity_check、稽核鏈、筆數比對通過 |
| 封存報告重現 | 單元測試 | 同版輸入、係數、規則重算結果一致；定版後改標的屬性不影響 |

## 6. 已知限制

- Email 通知需設定 SMTP，尚未實際寄送測試。
- 沒有做長時間（數日）穩定性測試與多程序部署測試。
- 預設係數、不確定性預設值與數據品質評分門檻須由院方核對後才能作為正式申報依據。
